# Архитектурный дизайн системы

## Типы данных

**ST7735S_ctx_t** - Аппаратно-независимая часть содержит только логику работы с дисплеем
```C
typedef struct {
  ST7735S_Write_Func   WriteReg;
  ST7735S_Send_Func    SendData;
  void                *handle;  
} ST7735S_ctx_t;
```

**ST7735S_IO_t** - Аппаратно-зависимая часть содержит реализации для конкретной платформы
```C
typedef struct {
  ST7735S_Init_Func          Init;
  ST7735S_DeInit_Func        DeInit;
  ST7735S_WriteReg_Func      WriteReg;
  ST7735S_SendData_Func      SendData;
  ST7735S_Delay_Func         Delay; 
} ST7735S_IO_t;
```

**ST7735S_Object_t** - Объект дисплея
```C
typedef struct
{
  ST7735S_IO_t         IO;
  ST7735S_ctx_t        Ctx;   
  uint8_t              IsInitialized;
} ST7735S_Object_t;
```

## Пример

Полный цикл вызова рассмотрен на примере чтения регистра:

Когда драйверу нужно прочитать регистр, то происходит следующая цепочка вызовов:

- Драйвер вызывает ST7735S_write_reg(&pObj->Ctx, reg, pdata, length)
  - Это вызывает ctx->WriteReg(ctx->handle, reg, pdata, length);
  - ctx->WriteReg указывает на ST7735S_WriteRegWrap;
    - ST7735S_WriteRegWrap; преобразует handle в ST7735S_Object_t*
    - Вызывает pObj->IO.WriteReg(Reg, pData, Length);
      - Это вызывает аппаратно-зависимую реализацию, которая работает с физическим интерфейсом
